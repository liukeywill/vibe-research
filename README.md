# Vibe Research · 统一科研工作流

从研究方向推进到文献、设计、验证、分析、论文写作和评审。**一个入口，两种模式**：默认逐阶段人工核查，也可明确选择连续自动成稿。

| 模式 | 适合的任务 | 推进方式 |
|---|---|---|
| 人工核查 | 需要自己判断选题、方法、证据和结论 | 每阶段交付成果与核查清单，等待研究者决定 |
| 自动成稿 | 主题已明确，希望连续完成研究与论文材料包 | 在真实证据和工具允许范围内连续执行，必要条件缺失时如实停止 |

研究规范与工具在本仓库统一维护，只需安装本技能。公众号、报道、日常文书和普通表达编辑使用 [Vibe Writing](https://github.com/liukeywill/vibe-writing)。

## 安装

需要 Python 3、网络连接及 Codex 的 skill-installer：

```bash
python3 ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo liukeywill/vibe-research \
  --path . \
  --name vibe-research
```

安装后在下一条消息中调用。已有同名目录不会直接覆盖，更新前先备份原安装；正在进行的项目和冻结快照保留。统一使用 `$vibe-research` 调用；不再提供旧名称兼容调用。

结构化自动执行需要 requirements.txt 中的 jsonschema，数值分析另需对应库。部分科研方法与 Word、PDF 制作依赖当前环境实际可用的技能与工具；安装入口不等于这些能力都已接通。

## 人工核查模式：研究者逐阶段把关

```text
$vibe-research
模式：人工核查
研究方向：AI反馈如何影响大学生的写作修改能力
目前只有课堂观察，还没有确定研究问题。
```

也可以只给研究方向，默认从人工核查模式开始。不要求先填完整表格；助手建卡、比较候选问题，交付当前阶段成果与3—6个人工核查问题，再停下。

| 阶段 | 主要成果 | 人工核查重点 |
|---|---|---|
| 1 问题收敛 | 候选问题、问题说明书 | 价值、范围、证据和资源；选定主要问题 |
| 2 文献证据 | 检索记录、文献矩阵 | 原文存在、是否支持概括、反对证据与检索盲区 |
| 3 研究设计 | 方法、指标与分析计划 | 方法能否回答问题、参数与替代解释 |
| 4 最小验证 | 试验或推导、实际输出 | 是否执行、能否复算、关键风险与可行性 |
| 5 正式执行 | 数据、代码、分析和日志 | 处理规则、负面结果、偏离与复现 |
| 6 论证写作 | 主张—证据表、提纲与初稿 | 先确认论证表，再核查初稿与结论强度 |
| 7 评审修订 | 意见表、人工取舍、修订记录 | 逐项决定接受、部分接受或不接受，之后修订 |
| 8 最终核验 | 定稿、核验报告和材料索引 | 版本对应、核验覆盖、剩余局限与最终接受 |

```text
阶段1已核查，采用方案B，研究对象限定为本科生，继续。
```

“方案B”应替换为实际选项。单独说“继续”不代表逐项核查通过；必要选择未给出时不推进依赖它的工作，未回答项保持未核查。AI 自检不能登记为人工确认。

## 自动成稿模式：连续完成论文与材料

```text
$vibe-research
模式：自动成稿
选题：城市遗产更新中的居民参与
学科：文旅与社会学
论文类型：整合性综述
字数：8000
请连续检索、整理证据、写作和审查，交付完整论文与材料包。
```

面向教育、社科与文旅，主题必填，其余参数可合理默认。依 scope → search → read → synthesize → design → analyze → package → review 连续执行，保留来源、证据、代码与结果的结构化记录。

默认按核心期刊投稿目标准备完整 Word、Markdown、JSON 论文，附检索、证据、分析和质量记录。目标不等于发表保证；结构检查不能证明语义、创新性或学术充分性。

没有真实数据且未限定类型时，可明确选择综述或理论论文；指定实证论文却缺不可替代数据时，保存已完成部分并标记未完成，不暗改类型、不编结果。内置数值分析适配器为 OLS＋HC3，其他方法按实际条件扩展。默认不逐阶段等批准，用户指定的人工交接与实际工具授权仍保留。

## 旧项目、恢复与模式调整

```text
$vibe-research 继续 /你的项目绝对路径
```

助手先检查实际项目记录，再恢复：

- 原人工项目沿用 project.md、state.json、decisions.md 和阶段成果。
- 原 Auto Paper 项目沿用 pipeline-state、profile、engine-manifest 和 runtime-snapshot；运行项目冻结脚本，不重新初始化。
- 升级技能不静默升级已有项目。状态损坏、材料缺失或模式冲突时先说明，不补造历史通过。

希望改变模式时明确提出，助手保留原项目，在新目录承接真实材料并核对缺口。人工确认和自动完成状态不互换；目前没有无损一键转换。

## 共用研究基础与来源

[Research Core](https://github.com/liukeywill/research-core) 随包内置，统一问题与设计、文献证据、主张审查、记录追溯；实际版本及固定来源提交见 [锁文件](shared/research-core.lock.json)。执行时无需另装模块或联网加载。新项目记录所用版本，旧项目继续使用原快照。

人工工作流依据用户提供的《AI重塑科研-Vibe Research-研究品味》及讨论整理，不分发原 PDF，不宣称官方实现。原 Auto Paper 的组件来源及许可见 [components.md](references/components.md)。本次整合保留这些来源，不为第三方内容重定许可证。

参考文献、数据、运行记录和人工决定不能编造；模拟与计划不作为实证结果。生成成果不自动授权外发、投稿或发布。
