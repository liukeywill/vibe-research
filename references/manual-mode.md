# 人工核查模式

目标：降低探索和实施成本，同时把选题、方法、证据与结论的关键判断保留给研究者。默认使用简体中文，遵循用户的语言选择。共用研究规范随包内置，不依赖另装 Auto Paper、Research Core、原始 PDF 或特定付费工具。

## 定位与共用基础

本模式保持“成果—人工核查—研究者决定—下一阶段”。用户选择连续自动成稿时按统一入口处理，不在进行中的人工项目里悄悄跳过核查。

首次启动或恢复先读 [共用基础适配与版本](research-core-adapter.md)，再按阶段读取随包 Research Core：

| 阶段 | 共用模块 |
|---|---|
| 1、3、4、5 | [问题、设计与验证](../shared/research-core/references/question-design.md) |
| 2及新增证据时 | [文献与证据](../shared/research-core/references/evidence.md) |
| 6、7、8 | [主张、写作与审查](../shared/research-core/references/claims-review.md) |
| 建卡、恢复与上游变更 | [记录与追溯](../shared/research-core/references/traceability.md) |

Research Core 只规定共同研究要求，不能替代下述人工核查规则。项目状态格式与自动模式不直接互通，迁移需核对材料和人工决定，不能把其自动阶段完成状态写成人工已核查。

## 首次启动

1. 输入只有研究方向时，从阶段 1 开始，帮助生成并比较候选研究问题；不要直接写论文或假定用户已选题。
2. 从用户提供的信息填写项目卡：领域、现象或矛盾、研究问题、对象与范围、预期贡献、已有材料、资源限制、目标成果、当前阶段、已确认决定、未解决问题。未知字段写“待明确”。
3. 最多提出 3 个影响当前阶段的具体问题；同时完成不依赖回答的分析。不要把填写全部字段作为启动前提。
4. 用户已有研究问题、材料或结果时，可进入对应阶段。先核对必要前置成果，缺失项标明“未核查”，不得虚构历史阶段已通过。
5. 默认在当前工作目录下的 `research-projects/<项目短名>/` 保存项目。目录冲突时复用用户确认的项目或使用新后缀，不覆盖其他项目。当前目录不适合写入时使用用户指定位置或询问保存位置；不能保存时交付可复制的恢复摘要，并说明尚未持久化。

## 八阶段

仅阅读 [references/stages.md](stages.md) 中当前阶段及必要前置部分；每阶段包含提示词、交付物、人工核查和通过条件。提示词是角色与任务模板，结合项目材料执行，不只是把模板转发给用户。

| 阶段 | 目标 | 主要成果 |
|---|---|---|
| 1 问题收敛 | 选择重要且可回答的问题 | 研究问题说明书 |
| 2 文献证据 | 确认已有知识与候选缺口 | 检索记录、文献矩阵 |
| 3 研究设计 | 明确方法、假设和判据 | 研究方案 |
| 4 最小验证 | 检查最可能导致失败的假设 | 试验或推导验证报告 |
| 5 正式执行 | 产生可追溯的真实证据 | 数据、代码、分析与复现记录 |
| 6 论证写作 | 让结论强度匹配证据 | 主张—证据表、提纲、初稿 |
| 7 评审修订 | 发现并解决实质性问题 | 意见表、人工决定、修订记录 |
| 8 最终核验 | 检查最新版本并准备交付 | 定稿、复现材料、核验报告 |

阶段 6 分为“论证表确认”与“初稿”两个子步骤；阶段 7 分为“审查意见—人工取舍—修订”三个子步骤，不能擅自跨过人工决定。

## 人工核查规则

- 每阶段完成后，必须先交付成果、人工核查清单、待决定项和下一步建议，再停在本阶段。不能在同一轮自动执行下一阶段。
- 使用以下固定收尾格式，内容根据当前阶段填写：

  **当前阶段与状态：** 阶段 N，等待人工核查。

  **本阶段成果：** 文件路径或可直接检查的内容。

  **请人工核查：** 3—6 个具体且可回答的问题。

  **待决定项与未验证项：** 明确列出；没有时写无。

  **下一步：** 请回复核查结果与决定，例如“阶段 N 已核查，采用方案 B，继续”、指出修改，或暂停。

- 单独的“继续”可以授权下一步工作，但不等于用户逐项阅读过文献或核查过数据。有待选择方案时仍需实际选择；其他情况下可将该回复记录为推进决定，未回答核查项仍保留“未核查”，不宣称核查通过。
- 首次记录“只管继续”“自动推进”这类总体偏好时，说明本工作流仍保留逐阶段核查。用户明确要求重设流程时可以调整，但不能把未验证证据写成已验证；不得伪造人工决定。
- 无证据支撑的关键结论必须撤回、收窄或等待验证。用户可以选择暂停、换题、退回修改或继续开展不依赖该结论的工作。
- 阶段完成不代表论文正确或可发表，AI 评审不等同于正式同行评审。

## 进度与恢复

启动或恢复项目时阅读 [references/project-state.md](project-state.md)。在项目目录保存：

- `project.md`：项目卡；
- `state.json`：阶段、状态、成果路径、未决项；
- `decisions.md`：追加式人工决定记录；
- `stages/01-question/` 至 `stages/08-final/`：按需创建的阶段成果，不预建空目录。

每次阶段交付、用户决定、暂停或恢复时更新状态。用户说“继续上次科研”时优先读取当前项目；有多个候选时请用户选择，不任意续接。

恢复必须核实成果文件存在且与决定所指版本相符。旧阶段状态不证明文件已经执行或人工已阅读。改变研究问题、主要设计或数据后，将受影响的下游成果标记 `needs_recheck`，保留旧版并说明回退范围。

## 证据与执行纪律

应用对应阶段的 Research Core 规则，具体任务、阶段提示词与人工核查仍以 [stages.md](stages.md) 为准。缺工具时明确未检索／未读全文／未运行；助手自检与共享上下文的多视角不能写成独立人工验证。

默认在本对话执行，未经适用授权不启动子代理或外部模型。

本工作流不授权向外部模型上传未公开材料、发送、投稿、发布、付费或开展需机构批准的活动。准备可审阅材料后按实际授权处理；不因自动工具返回成功跳过研究者决定。

## 常见调用

- `$vibe-research 我的研究方向是：AI辅助科研写作。` → 建卡、问题收敛、交付候选问题并等待决定。
- `$vibe-research 继续 /绝对路径/research-projects/项目名` → 读取状态与成果，呈现已确认决定和未决项，从当前阶段继续。
- `回到研究设计阶段，调整主要指标` → 保存变更，标记受影响下游成果待复核。
- `暂停并给我恢复摘要` → 保存状态，交付项目位置、阶段、已完成内容、待决定项和恢复方式。
