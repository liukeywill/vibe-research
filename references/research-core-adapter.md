# Research Core 在人工核查模式中的应用

新项目读取 `shared/research-core.lock.json`，将完整 `shared/research-core/` 和锁文件复制到项目 `research-core/` 与 `research-core.lock.json`，保留目录结构。在 state.json 的可选 research_core 字段记录实际版本、来源提交和快照路径；缺少模块或校验不符时不联网补装，说明缺失并保留当前已完成材料。

已记录版本的项目从项目快照读取相应模块；核对文件哈希与锁文件，不用安装目录新版本覆盖旧快照。旧项目无此记录时标记“未记录共用模块版本”，保留原流程和决定；希望采用新模块时在当前阶段说明影响，由研究者决定，不回填历史通过。

共同要求使用本技能的现有文件表达，不新增强制 JSON 证据格式：

| 共同对象 | 本流程记录 |
|---|---|
| 研究问题与设计 | 阶段1说明书、阶段3方案、阶段4最小验证 |
| 来源与证据 | 阶段2检索记录和文献矩阵；各阶段的原始输出与定位 |
| 主张与论证 | 阶段6主张—证据表 |
| 审查与修订 | 阶段7意见、研究者逐项决定、修订与复核 |
| 版本、状态与核验 | project.md、state.json、decisions.md 与阶段8核验表 |

只有研究者的实际反馈才能登记人工确认。每阶段仍交付后停下；阶段6先确认论证表，阶段7先交意见、等人工取舍再修订。共享规范、同步脚本、哈希检查均不能替代这些环节。
